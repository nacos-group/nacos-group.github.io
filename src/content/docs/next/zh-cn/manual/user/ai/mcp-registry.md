# MCP 管理

Nacos 管理 MCP Server 的服务描述、工具、资源、协议、版本和端点，供 MCP Client、Agent、网关和路由组件发现与使用。3.3 将 MCP Server 纳入统一的 [AI 资源生命周期](./ai-resource-lifecycle.md)，可以先编辑草稿、审核后再发布。

## 管理内容

| 对象 | 管理内容 |
| --- | --- |
| MCP Server 资源 | 名称、命名空间、启用状态、可见范围和业务标签 |
| 定义版本 | 服务描述、协议、工具与资源定义，以及版本状态和标签 |
| 运行端点 | 实际提供服务的地址和运行状态 |

发布定义版本与启动 MCP Server 是不同的操作。远程 MCP Server 发布上线后，仍需要有可访问的运行端点；存量 API 转换场景还需要网关完成协议转换。

## 发布一个版本

在 3.3 新版控制台或生命周期管理接口中，按以下步骤变更 MCP 定义：

1. 创建草稿，填写服务描述、协议、工具和资源信息。修改已发布的定义时，基于已有版本创建新版本草稿。
2. 保存并检查草稿，确认工具参数和调用方式符合使用方预期。
3. 提交草稿。有已启用且支持 MCP 的 Pipeline 节点时进入审核；没有适用节点时，提交直接发布上线。
4. 审核结束后查看结果。`reviewed` 只表示审核完成；通过后发布，拒绝后先重新编辑再修改，或重新提交以重跑检查。
5. 确认版本为 `online`，再从 MCP Client、Agent 或网关验证发现与调用。

标准生命周期只允许编辑草稿，已发布或已下线的版本内容不能直接覆盖。管理员应急强制发布、重新编辑和上下线规则见 [AI 资源生命周期](./ai-resource-lifecycle.md)。

## 版本与可用性

- **默认版本**：标准发布和重新上线操作会自动将 `latest` 指向该版本，无需手动修改。
- **暂停一个版本**：下线目标版本；若它是 latest，服务端会从剩余在线版本中重新选择。调用方固定了版本或自定义标签时，需要同时检查其配置。
- **暂停整个 MCP Server**：禁用资源。重新启用不会自动发布草稿或上线已下线版本。
- **控制访问范围**：结合可见性和调用方权限管理访问。管理页面能看到资源，不代表所有运行时调用方都能使用。
- **检查端点**：定义已经上线但调用失败时，继续检查 MCP Server 进程、网络、端点和网关配置。

## 已有注册方式的兼容性

已有 MCP 创建、更新及 SDK 自动注册方式保留直接发布的兼容行为，不会因为升级到 3.3 就自动改为“先审核再发布”。旧接口选择默认版本的参数也保留兼容语义。

需要发布前审核时，应接入草稿、提交和发布流程。3.3 Java SDK 的 `releaseMcpServer` 新增 `createDraft` 重载参数：设为 `true` 时只创建草稿，不自动提交或上线；默认仍采用原有直接发布方式。使用前确认服务端支持该能力，并按生命周期流程完成后续发布。

已有集成是否使用新参数，取决于对应框架或组件的实现。不能仅通过启用 Pipeline，就假定原有自动注册请求一定会经过审核。旧接口兼容更新的行为也不能作为新草稿接口覆盖已发布版本的依据。
