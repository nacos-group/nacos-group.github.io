# Nacos Concepts

> NOTE: Nacos introduces some basic concepts and systematic understanding of these concepts can help you better understand and correct use Nacos products.

## Region
A physical data center where resources, once created, cannot be changed.

## Availability Zone
Within a region, physically independent zones for power and network. Low network latency exists among instances within the same availability zone.

## Access Point
The entry domain name of a service in a region.

## Namespace
Enables tenant-level configuration isolation. Under different namespaces, configurations with identical Group or Data ID can coexist. Namespaces are commonly used to separate environments like development/test from production, isolating resources such as configurations and services.

## Configuration
During system development, developers often separate changeable parameters and variables from code, managing them independently in configuration files. This allows static artifacts (e.g., WAR, JAR) to better adapt to actual runtime environments. Configuration management includes editing, storing, distributing, versioning, auditing, and adjusting system runtime behavior.

## Configuration Management
All activities related to configurations, including editing, storage, distribution, change management, historical version control, and audit trails.

## Configuration Item
An individual configurable parameter and its value range, typically presented as param-key=param-value. For example, logLevel=INFO|WARN|ERROR is a configuration item.

## Configuration Set
A collection of related or unrelated configuration items, usually constituting a configuration file encompassing various system aspects such as data sources, thread pools, and log levels.

## Configuration Set ID (Data ID)
The identifier for a configuration set in Nacos. It's a dimension for organizing configurations, following a naming convention akin to Java packages for uniqueness (e.g., com.taobao.tc.refund.log.level).

## Configuration Group
A set of configuration sets in Nacos, another organizational dimension. Meaningful strings (e.g., Buy or Trade) distinguish configuration sets with identical Data IDs. The default group name, if not specified, is DEFAULT_GROUP. Common scenarios include sharing configuration types across different applications or components.

## Configuration Snapshot
Local snapshots of configurations are generated by Nacos' client SDKs. These snapshots enhance disaster recovery when clients cannot connect to Nacos servers, resembling local commits in Git without expiration.

## Service
Software functionality provided over a network through predefined interfaces.

## Service Name
The identifier that uniquely determines a referenced service.

## Service Registry
A database storing service instances and load balancing policies.

## Service Discovery
Detects and provides query access to service instances and metadata within a computer network, typically via a service name.

## Metadata
Descriptive information about Nacos data (configurations and services), including service versions, weights, failover strategies, load balancing policies, authentication configurations, and custom labels applicable at the service, cluster, or instance level.

## Application
Attributes of a service indicating its provider.

## Service Grouping
Different services can be categorized under the same grouping.

## Virtual Cluster
All instances of a service form a default cluster, which can be further divided into virtual clusters as needed.

## Instance
A process with an accessible network address (IP:Port) providing one or more services.

## Weight
An instance-level setting determining traffic distribution; higher weight attracts more traffic.

## Health Check
Monitors the health of service instances to ensure their service capability, marking them as healthy or unhealthy based on the outcome. Unhealthy instances are excluded from client queries during service resolution.

## Health Protection Threshold
To avoid overwhelming healthy instances with traffic when many instances are unhealthy, this threshold, a float between 0 and 1, ensures a minimum percentage of healthy instances are always returned to clients, preventing cascading failures even if it means sacrificing some traffic.
